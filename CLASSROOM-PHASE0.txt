CLASSROOM — เฟส 0: บัญชีและสิทธิ์
อัปเดต: 14 กันยายน 2026

ขอบเขตรอบนี้
หน้า Classroom แยกผู้เยี่ยมชม / กำลังตรวจสิทธิ์ / นักเรียน / ครู / ตรวจไม่สำเร็จ
ใช้ Google Login และสิทธิ์จาก Firebase Realtime Database เดิม
ยังไม่สร้างห้อง สมาชิก งาน หรือสมุดคะแนน และไม่ต้องเชื่อม Google Classroom
ไม่ได้เพิ่มครูด้วยการเช็กชื่อหรืออีเมลในหน้าเว็บ ต้องเป็น UID ที่ได้รับอนุมัติจริง

สิ่งที่ทำในโค้ด
- ผลตรวจสิทธิ์ผูกกับ UID ของเจ้าของผล ไม่เอาผลบัญชีก่อนหน้ามาใช้กับบัญชีใหม่
- สิทธิ์ครู/แอดมินไม่แสดงระหว่างตรวจยังไม่ครบ หรืออ่านข้อมูลสิทธิ์สำคัญล้มเหลว
- คำขอเป็นครูที่รออนุมัติยังเป็นนักเรียน คำว่า approved ในคำขอไม่ใช่สิทธิ์ครู
- ปุ่มตรวจสิทธิ์อีกครั้งเริ่มฟังข้อมูลบัญชีปัจจุบันใหม่ และยกเลิกตัวฟังเก่า
- ออกจากระบบหรือสลับบัญชีล้างชื่อ ข้อความคำขอ ฟอร์ม และปิดแผงสิทธิ์บัญชีก่อนหน้า
- เปิด Classroom โดยตรงจะแจ้งให้เข้าผ่าน Hub ไม่อนุมานบัญชีจาก URL
- ระบบเมนูรายวิชาและ Quiz เดิมยังใช้ร่วมกันได้

วิธีลองของจริงในเครื่อง
1. เปิด Learning Hub ผ่านเซิร์ฟเวอร์ในเครื่อง แล้วเลือกแท็บห้องเรียน
   ลิงก์ที่เตรียม: http://127.0.0.1:3005/#classroom
   ลิงก์นี้ใช้ได้เฉพาะเครื่องที่เปิดเซิร์ฟเวอร์ ไม่ใช่ลิงก์สำหรับ iPad อีกเครื่อง
2. โหมดผู้เยี่ยมชมควรเห็นปุ่มเข้าสู่ระบบ ไม่เห็นพื้นที่ครู
3. เข้าด้วยบัญชีครูที่ระบุไว้ในการสนทนา
   - หากอนุมัติแล้ว: เห็นพื้นที่จัดการห้องเรียนและอีเมลตัวเอง
   - หากยังไม่อนุมัติ: เห็นมุมมองนักเรียน หรือคำขอรออนุมัติ
   - หากอ่านสิทธิ์ไม่ได้: เห็นตรวจไม่สำเร็จ ไม่ใช่เดาว่าเป็นนักเรียน
4. ออกจากระบบและเข้าด้วยบัญชีทดสอบนักเรียน ควรเหลือชื่อและมุมมองของบัญชีใหม่
5. สลับไปแท็บวิชาแล้วกลับห้องเรียน สิทธิ์ต้องยังตรงบัญชี
6. ลองภาษาไทย/อังกฤษ และทดสอบบน iPad หลังเผยแพร่รุ่นนี้แล้ว
   ไม่ต้องส่งรหัสผ่านหรือรหัส OTP ให้ผู้พัฒนา

ตรวจ Firebase ก่อนถือว่าผ่านจริง
ยังไม่ได้อ่าน/แก้ Rules ที่ติดตั้งจริง และยังไม่ได้ทดสอบ Rules ด้วย Emulator
การทดสอบจำลองในโค้ดไม่ใช่หลักฐานว่าฐานข้อมูลจริงป้องกันการเข้าถึงแล้ว
ผู้ดูแลต้องตรวจ Rules ปัจจุบันก่อนปรับใด ๆ โดยสำรองและไม่แทนที่กฎเดิมทั้งไฟล์
ใช้ FIREBASE-RULES-ROUND3.md เป็นข้อมูลประกอบ ไม่คัดลอกทับโดยไม่ตรวจ

รายการตรวจสิทธิ์ (Rules Playground / Emulator ก่อนใช้กับข้อมูลจริง)
- ไม่ล็อกอิน: อ่านข้อมูลสิทธิ์ส่วนตัวและเขียนคำขอไม่ได้
- นักเรียน A: อ่านสถานะตัวเองได้ แต่เขียน admins หรือ teacherApprovals ไม่ได้
- นักเรียน A: ส่งได้เฉพาะคำขอ pending ของตัวเอง อนุมัติคำขอตัวเองไม่ได้
- นักเรียน A: อ่านคำขอ/โปรไฟล์ส่วนตัวของ B หรือรายชื่อทั้งกิ่งไม่ได้
- ครู: ไม่ได้สิทธิ์แอดมินเพียงเพราะเป็นครู และไม่อ่านคลังข้อมูลทุกคน
- Quiz เดิม: ยังอ่าน/เซฟเฉพาะข้อมูลเจ้าของบัญชีได้
- ไม่เพิ่มกฎเปิดอ่านคะแนนของทุกคนในเฟสนี้

สำคัญ: ห้ามมี .read หรือ .write ที่เปิดกว้างในกิ่งแม่โดยคิดว่ากฎลูกจะปิดได้
Firebase ให้สิทธิ์แบบสืบทอดจากกิ่งแม่ กฎลูกที่ false ไม่ถอนสิทธิ์ที่กิ่งแม่ให้แล้ว
อ้างอิง: https://firebase.google.com/docs/database/security/core-syntax

ผลตรวจในเครื่อง
- ชุดทดสอบ logic ของ Classroom ใช้ roles.js จริงกับ Firebase จำลอง
- ทดสอบหน้า Hub จริง: guest, รอสิทธิ์, ครู, นักเรียน 2 คน, รออนุมัติ,
  ถอนสิทธิ์, อ่านสิทธิ์ผิดพลาดและ retry, callback เก่า, แหล่งข้อความผิด,
  สลับแท็บ, ภาษา, หน้าจอแคบ, ออกจากระบบ และเปิดหน้าโดยตรง
- ทดสอบการเปิด Quiz จากเมนูบท/เรื่องและการเก็บคำตอบเดิม
- ทุกบัญชีในชุดทดสอบอัตโนมัติเป็นข้อมูลสมมติ ไม่ยิง Firebase หรือ Worker จริง

งานถัดไปเมื่อยืนยันเฟส 0

ยังไม่เริ่มทำในรอบนี้
