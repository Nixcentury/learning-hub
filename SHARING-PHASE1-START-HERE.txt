รูปแบบลิงก์
-----------
#physics                                      หน้าเลือกบทฟิสิกส์

#chemistry/10/acid-base-theories               เรื่องย่อยทฤษฎีกรด–เบส

ใช้ # ครั้งเดียว แบ่งชั้นด้วย / และใช้รหัสอังกฤษตัวเล็ก ตัวเลข ขีดกลาง
content กับ tool เป็นชื่อสงวนสำหรับทางเข้ากลาง ไม่ใช้ตั้งเป็นรหัสวิชา
บทที่มีปุ่มสรุปใช้ overview เป็นปลายทางท้ายบท อย่าตั้งเรื่องย่อยซ้ำตำแหน่งนี้
ลิงก์ระบุตำแหน่งเนื้อหา ไม่เก็บคำตอบ โน้ต คะแนน UID หรือสิทธิ์บัญชี
การมีลิงก์ไม่ใช่การได้รับสิทธิ์ ห้องเรียนส่วนตัว/รายงานคะแนนยังไม่อยู่ในสารบัญนี้

ครูต้องทำอะไรเพิ่มไหม
--------------------
ถ้าใช้รหัสเดิม ไม่ต้องทำอะไรเพิ่ม เพิ่มชื่อและ href ใน HTML ตามคู่มือเดิมได้เลย
ระบบอ่านแท็บจาก index.html อ่านบทจาก public/pages/<วิชา>.html
แล้วไล่เมนู data-chapter-src, เรื่องย่อย, รายการเครื่องมือ, ปุ่มสรุป และ data-hub-html
ไฟล์ที่วางเฉย ๆ แต่ยังไม่มีลิงก์จากเมนู/หน้าเว็บจะไม่ถูกประกาศเป็นเนื้อหาในสารบัญ
เรื่องย่อยไม่มี href และปุ่มสรุปที่ระบุปลายทางว่างจะมีสถานะ preparing
บทที่ยังใช้เมนูเดิมมีสถานะ legacy ไม่อ้างว่ามีเมนูเรื่องย่อยพร้อมแล้ว
บทใหม่ที่ยังไม่มีทั้งเมนู HTML และเครื่องมือรุ่นเก่าจะมีสถานะ preparing ได้ ไม่ต้องสร้างไฟล์เปล่า
เมื่อพร้อมให้เชื่อมเมนู HTML ของบทนั้น จึงจะมีรายการงานของบทในสารบัญ

ถ้าต้องการชื่ออ่านง่ายในลิงก์ (เลือกทำภายหลังได้)
----------------------------------------------
เพิ่ม data-route-slug บน article ของบท โดยไม่เปลี่ยน data-chapter เช่น:
<article data-chapter="1" data-route-slug="natural">

ระบบกำหนดชื่อหลักเป็น #physics/natural แต่ยังรู้จัก #physics/1
data-route-slug ใส่บนลิงก์เรื่องย่อยและรายการเนื้อหาในเมนูได้ด้วย
เมื่อเปลี่ยนชื่อเสริมภายหลัง ให้เก็บชื่อเก่าด้วย data-route-aliases เช่น:
<article data-chapter="1" data-route-slug="nature" data-route-aliases="natural">
หลายชื่อเก่าคั่นด้วยช่องว่าง ชื่อเก่าจะใช้กับเส้นทางลูกด้วย
อย่าเปลี่ยน slug ที่แจกแล้วโดยลบชื่อเก่าออก ระบบไม่ได้จำชื่อเก่าจากประวัติ Git เอง
เฟสนี้ยังไม่ได้ตั้งชื่อเสริมแทนครูหรือแก้ HTML เนื้อหาจริง

Quiz เดียวอยู่หลายเรื่อง
----------------------
ใช้ data-content-id และไฟล์ปลายทางเดิมในหลายเมนูได้
สารบัญจะมีเนื้อหาหนึ่งรายการพร้อมตำแหน่งที่เปิดได้หลายแห่ง
รหัสเดียวกันห้ามชี้คนละไฟล์/คนละประเภท ถ้าพบระบบจะหยุด Build พร้อมบอกต้นเหตุ
สำหรับ HTML อ่านอย่างเดียว ไฟล์เดียวกันต้องใช้ data-content-id เดียวกันทุกลิงก์
สำหรับ Quiz/Simulation รหัสในเมนูต้องตรง data-activity-id ของไฟล์ปลายทาง
ย้ายไฟล์ได้หากแก้ href ให้ถูกและคงรหัส/slug เดิม ลิงก์ประจำเนื้อหายังใช้รหัสเดิม

ข้อสำคัญสำหรับเครื่องมือรุ่นเก่า
-------------------------------
test-c2-quiz คือรหัสงานที่ระบบเซฟใช้อยู่ แม้ HTML ข้างในมีรหัส numeric-input-demo-v1
เฟสนี้รักษา test-c2-quiz ไว้ ไม่ย้ายคำตอบไปผูกกับรหัสใหม่
รายการเครื่องมือเดิมย้ายมาเก็บใน js/legacy-tool-catalog.js เพื่อใช้ข้อมูลชุดเดียวกัน
หน้าต่างและสารบัญจึงไม่ต้องมีรายการรุ่นเก่าคนละสำเนา
เพิ่มเนื้อหาใหม่ผ่านเมนู HTML ไม่ต้องเพิ่มรายการในไฟล์รุ่นเก่านี้

ตรวจสอบในเครื่อง
----------------
pnpm validate:routes     ตรวจรหัส เส้นทาง ไฟล์ปลายทาง และพิมพ์จำนวนรายการ ไม่เขียนไฟล์
pnpm test:unit           ตรวจระบบเดิมและสัญญาลิงก์
pnpm build               ตรวจเนื้อหาและสร้างเว็บ พร้อม route-catalog.v1.json ใน dist

สารบัญเป็นไฟล์ที่สร้างอัตโนมัติทุก Build ไม่แก้และไม่ Commit ไฟล์ใน dist ด้วยมือ
เมื่อใช้ pnpm dev มี endpoint /route-catalog.v1.json สำหรับทดสอบ อ่าน HTML ล่าสุดทุกครั้ง
เมื่อเผยแพร่ จะอยู่ใต้ /learning-hub/route-catalog.v1.json โดยไม่มี path เครื่องครูหรือคำตอบโจทย์
ไฟล์สารบัญเพียงอย่างเดียวยังไม่ได้ทำให้ URL เปลี่ยนตามคลิกหรือเปิด Quiz อัตโนมัติ
