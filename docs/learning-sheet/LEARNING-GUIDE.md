# ไกด์ประจำใบเรียนรู้

ปุ่มกลาง **ไกด์ใบนี้ / Sheet guide** อยู่บนแถบหน้าต่างใบเรียนรู้ ทุกคนใช้ได้รวม Guest ไกด์ช่วยเลือกทางเดินในคาบหรือเรียนเอง โดยเก็บใบฉบับเต็มไว้สำหรับศึกษารายละเอียด ไม่มีการคิดคะแนนหรือตรวจสิทธิ์ครู

## สิ่งที่ผู้สร้างใบต้องส่ง

ใบใหม่ให้ส่ง HTML พร้อมไฟล์ `*.guide.json` ประจำใบนั้น ถ้าแบ่งเป็นหลายชุด แต่ละชุดมีไกด์ของตัวเอง ใบเก่าที่ยังไม่ได้ทำไกด์เปิดใช้งานต่อได้ ปุ่มจะแจ้งว่ายังไม่มีไกด์ ห้ามแต่งไกด์อัตโนมัติจากหัวข้อเพียงอย่างเดียวเพื่อให้ดูเหมือนทำครบแล้ว

ตัวอย่างจริง: [19.1 ชุดที่ 2](../../public/content/physics/ipst/atomic-physics/guides/19-1-2b.guide.json) คู่กับ [HTML](../../public/content/physics/ipst/atomic-physics/19-1-2b-bohr-radius-energy-learning-sheet.html)

## เนื้อหาไกด์

เริ่มด้วยพื้นฐานที่ควรทวนและเป้าหมาย 1–2 ประเด็น แบ่งทางเดินตามหัวข้อจริงในใบเป็นช่วงสั้น ๆ แต่ละช่วงต้องมีครบ:

| ฟิลด์ | สิ่งที่เขียน |
| --- | --- |
| `title` | ชื่อช่วงที่อ่านเข้าใจทันที |
| `summary` | **สรุปเนื้อหาจากส่วนนั้น 2–4 บรรทัดเสมอ** เก็บสูตร หน่วย เงื่อนไขและข้อยกเว้นสำคัญ ไม่เขียนเพียงว่า “ไปอ่านหัวข้อ…” |
| `story` | เริ่มเล่า/ชวนคิดอย่างไร ชี้รูป ตาราง หรือความเข้าใจผิดใด ภาษาที่ครูหยิบไปพูดหรือนักเรียนอ่านเองได้ |
| `action` + `links` | งานขั้นต่ำที่ควรลงมือ เลือกข้อที่ใช้ความคิดต่างกัน ระบุชื่อหัวข้อและเลขข้อจริง พร้อมปุ่มไปยังตำแหน่งจริง |
| `check` | คำถามสั้นชัดและแนวคำตอบ ใช้บอกว่าเข้าใจแก่นแล้วหรือยัง คำตอบพับไว้ให้ลองเองก่อน |
| `review` | ปุ่มกลับไปดูส่วนที่ช่วยแก้ความสับสน ถ้ามี |
| `after` | ถ้าผ่านแล้วไปไหนต่อ ถ้ายังไม่คล่องเลือกฝึกอะไร ไม่สั่งทุกช่องที่เหลือเป็นการบ้านโดยอัตโนมัติ |

จบด้วย `finish` สรุปสิ่งที่ควรเชื่อมได้ และ `exitCheck` คำถามปิดท้ายพร้อมแนวคำตอบ ไกด์เป็นตัวช่วยเลือกใช้ใบ ไม่ยกเฉลยทั้งใบมาซ้ำ ทุกข้อความเป็นคู่ `{ "th": "…", "en": "…" }` เนื้อหาตรงกัน ใช้ข้อความธรรมดาและสัญลักษณ์ Unicode เช่น `K = −E`, `rₙ = a₀n²` ห้าม HTML หรือ LaTeX ดิบในไกด์ สูตรพิสูจน์เต็มยังอยู่ในใบ

**สรุปต้องจัดทำจากเนื้อหาจริงและตรวจโดยผู้เขียน** ระบบอ่านสรุปที่จัดทำไว้มาประกอบทุกช่วง ไม่ตัด DOM หรือสร้างคำสรุปใหม่ขณะนักเรียนเปิดอ่าน จึงควบคุมความถูกต้องและการอ้างอิงได้

## การผูกไฟล์และตำแหน่ง

เพิ่มบนราก HTML เท่านั้น ไม่สร้างปุ่มหรือสคริปต์ในเนื้อหา:

```html
<html data-learning-html data-learning-sheet="1"
      data-sheet-guide="guides/your-sheet.guide.json"
      data-sheet-revision="2026-10-29-1">
```

โครงไฟล์ JSON ใช้ `schemaVersion: 1`, `source: {contentId, revision, sha256}`, `title`, `prerequisites`, `goal`, `steps`, `finish`, `exitCheck` ยึดไฟล์ตัวอย่างที่ผ่าน validator เป็นแม่แบบ จำกัด 128 KiB และไม่เกิน 20 ช่วง

แต่ละ step มี `id` ถาวรและ links รูปแบบนี้:

```json
{
  "label": { "th": "คำถาม 8", "en": "Question 8" },
  "target": { "kind": "slot", "key": "radius-ratio" }
}
```

ใช้ semantic key `data-sheet-slot` เดิมเป็นหลัก หากต้องชี้รูปหรือหัวข้อที่ไม่มีช่อง ให้ใส่ `data-guide-anchor="figure-example"` บนองค์ประกอบนั้น **ทั้ง TH และ EN** แล้วใช้ `kind: "anchor"` ต้องพบเป้าหมายเพียงหนึ่งจุดต่อภาษา ห้ามใช้เลขลำดับย่อหน้า เลขหน้า PDF หรือ URL ภายนอกแทนตำแหน่ง

ไฟล์ไกด์ต้องอยู่ใต้ `public/content/` ใช้พาธภายในเว็บลงท้าย `.guide.json` ไม่มี query/hash ไม่เปลี่ยน `contentId` หรือ tool-key ของใบเดิม ระบบกระโดดไปเป้าหมายภาษาที่กำลังเปิดและเน้นกรอบชั่วคราว โดยไม่เปิดเฉลยเอง

## เมื่อแก้ใบหรือไกด์

1. ตรวจทุกสรุป เลขข้อ และ target ให้ตรงกับใบฉบับใหม่ ทั้งสองภาษา
2. เปลี่ยน `data-sheet-revision` ใน HTML และ `source.revision` ใน JSON ให้ตรงกัน
3. หลัง HTML เสร็จ รัน `node scripts/validate-learning-guides.mjs --fingerprint public/content/.../sheet.html` แล้วใส่ค่าที่ได้ใน `source.sha256` การเปลี่ยน hash เป็นขั้นหลังตรวจเนื้อหา ไม่ใช่ทางลัดให้ผ่าน
4. รัน `pnpm validate:guides` และ checks ของงานตามปกติ `pnpm build` รวมการตรวจนี้แล้ว

ตัวตรวจเทียบ contentId กับ catalog จริง ตรวจ revision ลายนิ้วมือ HTML และเป้าหมายครบทั้งสองภาษา การแก้ HTML แม้ target เดิมยังอยู่จะทำให้ตรวจไม่ผ่านจนทบทวนไกด์ ส่วน runtime ตรวจ identity/revision/targets ก่อนแสดง หากโหลดไม่ได้ยังอ่านใบเต็มต่อและกดลองใหม่ได้

## QA หน้าจอและพิมพ์

- ทุกคนกดได้รวม Guest; ใบที่ไม่มีไกด์แสดงสถานะชัดเจน
- ลอง TH/EN เปิดแนวคำตอบ ปิด/เปิดไกด์ และเปิดสองใบพร้อมกัน ไกด์ไม่ปะปนกัน
- กดปุ่มทุก target ตรวจว่าถูกภาษา ถูกข้อ และไม่เปลี่ยนการเปิดเฉลยหรือขนาดพื้นที่ตอบ
- จอกว้างใช้แผงข้าง หน้าต่างแคบใช้ drawer; ปิดด้วยปุ่มหรือ Escape ได้ ใช้คีย์บอร์ดและมือถือได้
- ไกด์ไม่เข้าเอกสารพิมพ์ ตรวจฉบับว่าง/เฉลยทั้งสองภาษา เนื้อหา จำนวนช่อง และรูปต้องยังครบ

ห้ามลดเนื้อหาเดิมเพื่อให้ไกด์สั้น และห้ามเพิ่มระบบคะแนน การบ้าน สิทธิ์บัญชี หรือการบันทึกความก้าวหน้าโดยไม่มีขอบเขตงานรองรับ
