## เนื้อหาและวิธีสอน

- [ ] อ่านต้นฉบับช่วงที่ระบุจริง รวมรูป คำบรรยาย ตาราง ตัวอย่าง กิจกรรมและข้อท้ายหัวข้อ
- [ ] ตารางติดตามแสดงว่าข้อจากหนังสือแต่ละข้อไปอยู่ที่ใด ครบตามขอบเขตที่ตกลง
- [ ] มีหัวข้อเนื้อหาให้เขียนและคำถามค่อย ๆ ย่อยความรู้ ไม่เป็นชีทอ่านหนาแน่นหรือคำถามล้วน
- [ ] ไม่มีป้ายจุดเช็ก/จด/จำ/ฝึกเพิ่มที่แต่งเพิ่ม หัวข้อบอกเนื้อหาโดยตรง
- [ ] ทุกคำถามและทุกข้อย่อยมีพื้นที่ตอบใต้ข้อนั้น ขนาดพอสำหรับคำตอบ/ขั้นคำนวณ
- [ ] เลขข้อ ตัวอย่าง และการอ้าง “จากข้อก่อน/ข้อ...” ถูกต้องหลังจัดลำดับใหม่
- [ ] เฉลยหัวข้อความรู้และโจทย์ครบ ตรวจเหตุผล สูตร หน่วย เงื่อนไข ข้อยกเว้น และการประมาณ
- [ ] โจทย์คำนวณคำนวณใหม่เทียบคำตอบ ไม่รับรองด้วยการดูว่ามีสูตรอยู่แล้ว
- [ ] ข้อที่เพิ่มมีวัตถุประสงค์และความยากต่อเนื่อง แยกแหล่งเดิม/ข้อดัดแปลง/ข้อแต่งใหม่ไว้ในบันทึก
- [ ] TH/EN ตรงกันทั้งลำดับ ตัวเลข ข้อย่อย รูป ตาราง สูตรและคำตอบ

## ภาพและไฟล์

- [ ] รูปทั้งหมดมีไฟล์จริง relative path เปิดได้ ไม่มี placeholder หรือ hotlink ที่อ้างว่าสร้างแล้ว
- [ ] รูปต้นฉบับที่จำเป็น โดยเฉพาะรูปโจทย์ ไม่หายหรือตัดลูกศร/สเกล/หน่วยสำคัญทิ้ง
- [ ] ภาพชุดควบคุมรูปร่าง มุมมอง สเกล และตัวแปรเปรียบเทียบสอดคล้องกัน
- [ ] แผนภาพวิทยาศาสตร์ตรวจตำแหน่ง มุม ระยะ ทิศและความหมายของเส้นได้
- [ ] รูปมีอัตราส่วนถูกต้อง width/height และ alt ไม่เปิดคำตอบที่ต้องซ่อน
- [ ] assets มีบันทึกแหล่ง หน้า/รูปที่ตัด และสิ่งที่สร้างเพิ่ม

## สัญญา Learning Sheet และไอดีคลัง

- [ ] ยืนยัน bankKey/หัวข้อจากหน้าคลังหรือ catalog จริง ไม่ใช้ ID ตัวอย่าง/ID ชุดข้อสอบรายปีแทน
- [ ] เมนู `content/bank/<subjectId>/<bankKey>.html` และ nav ตรงกับหัวข้อ ปุ่มใบเรียนรู้ชี้ HTML จริง
- [ ] contentId/tool-key ไม่ชน รักษา ID ของงานเดิมและรายการอื่นในเมนู
- [ ] HTML มี learning-sheet marker, print metadata, shared CSS path และ TH/EN blocks ถูกต้อง
- [ ] semantic slot key เป็นคู่ครบ แต่ละ slot มี answer ลูกโดยตรงหนึ่งตัว ไม่ซ้อน slot
- [ ] คำตอบอยู่ใน answer ไม่มีคำตอบรั่วใน label/alt/attribute หรือข้อความซ้ำด้านนอก
- [ ] ใช้ `data-sheet-*` ของ Learning Sheet ไม่สลับกับ `data-review-*` ของ Topic Review
- [ ] ไม่มี script/handler/form/iframe/toolbar หรือ engine ใหม่ในไฟล์เนื้อหา ไม่มีการแก้ข้อมูลนักเรียน
- [ ] กลุ่ม `data-print-keep` เล็กพอ ไม่ครอบทั้งช่วงยาว และไม่มี CSS ตัดข้อความ/ทับระบบพิมพ์

## ตรวจอัตโนมัติ

รันตามคู่มือและขอบเขตที่แก้ งานใบใหม่ให้ตรวจ content, routes และ production build; รัน unit checks ที่คู่มือกำหนด/เกี่ยวข้อง บันทึกคำสั่งและผลจริง ไม่ใส่จำนวน tests เก่าจากตัวอย่าง

| คำสั่ง | ผล/จำนวน errors และ warnings จริง | หลักฐาน |
| --- | --- | --- |
| `pnpm validate:content` | ยังไม่รัน | |
| `pnpm validate:routes` | ยังไม่รัน | |
| `pnpm test:unit` | ยังไม่รัน | |
| `pnpm build` | ยังไม่รัน | |
| `git diff --check` | ยังไม่รัน | |

`pnpm build` รวม content validation ตาม package.json ปัจจุบัน ถ้าตรวจสำเร็จแล้วและไฟล์ไม่เปลี่ยน ไม่ต้องรันคำสั่งเดิมซ้ำเพียงเพื่อเติมตาราง ให้ระบุว่าผลมาจาก build เดียวกัน ระบุ existing draft warnings ให้ชัด ไม่ลดข้อผิดพลาดเป็น warning เพื่อให้ผ่าน

## หน้าจอใน Hub จริง

- [ ] เปิดผ่านหัวข้อ/ไอดีเป้าหมายและลิงก์ตรงได้ ไม่ตรวจเฉพาะ HTML standalone
- [ ] TH/EN ทำงานและไม่มีข้อความสองภาษาซ้อน
- [ ] เปิด/ปิดรายช่อง เปิดทั้งหมด/ปิดทั้งหมดทำงาน และพื้นที่คำตอบไม่กระโดดยุบเมื่อเปิด
- [ ] คงสถานะเฉลยที่ควรคงเมื่อสลับภาษา/กลับจากพิมพ์ตามระบบเดิม
- [ ] รูปโหลดครบ สูตร render ไม่มี error และจำนวนช่อง/คำถามครบ
- [ ] ตรวจจอแคบ: หัวข้อ คำถาม สูตร รูปและช่องตอบไม่ล้นแนวนอน

ระบุ browser และความกว้างที่ตรวจ ถ้าใช้ iframe fixture ให้ระบุว่าเป็นการตรวจเนื้อหาใน iframe ไม่ใช่ native iPad หรือ mobile Hub ทั้งระบบ ห้ามทดสอบด้วยการเขียนคะแนน/ข้อมูลนักเรียนจริง

จำนวนหน้าใช้ค่าที่ตรวจจริง ไม่บังคับให้เท่าตัวอย่างหรือเท่ากันทุกภาษา ตรวจว่าอีกภาษาถูกเอาออกจากสำเนาพิมพ์ ฉบับว่างลบ answer ออกจาก DOM จริง ไม่ใช่ทำตัวอักษรขาว ตรวจภาพและสมการทุกหน้า ไม่รับรองเฉพาะจาก page count

## แยกขอบเขตหลักฐาน

| ประเภท | สถานะและหลักฐานจริง |
| --- | --- |
| อ่านเนื้อหา/คำนวณ/ตรวจต้นฉบับ | ยังไม่ตรวจ |
| Browser หน้าจอ Hub | ยังไม่ตรวจ |
| จอแคบ / iframe fixture | ยังไม่ตรวจ |
| Central print preview | ยังไม่ตรวจ |
| PDF ที่ export และเปิดตรวจไฟล์จริง | ยังไม่ตรวจ |
| Native iPad/Safari | ยังไม่ตรวจ |

กรอก “ยังไม่ได้ทดสอบ” เมื่อไม่มีหลักฐานนั้น การผ่าน preview ไม่ใช่การผ่าน native PDF driver หรือ Safari หากเครื่องมือขาดให้ส่งสิ่งที่ทำเสร็จและระบุผู้รับช่วง/วิธีตรวจต่อ ไม่สร้างผล QA สมมติ

## เผยแพร่และส่งกลับ

- [ ] ตรวจ diff เทียบ main ล่าสุด เปลี่ยนเฉพาะไฟล์งานนี้และรักษางานของผู้ช่วยอื่น
- [ ] commit/branch/PR ที่ส่งตรงกับชุดไฟล์ที่ตรวจ
- [ ] ถ้าได้รับสิทธิ์เผยแพร่แล้ว Actions build/deploy สำเร็จ และ deployment.json ตรงกับ commit ที่เผยแพร่
- [ ] เว็บจริงมีเมนู/route พร้อม เปิดใบได้ และไฟล์ที่เปลี่ยนตรงกับชุดที่ตรวจ
- [ ] ส่งลิงก์ตรงที่ตรวจแล้ว พร้อมสรุปงานและข้อจำกัด หากยังไม่เผยแพร่ให้ใช้คำว่าไฟล์/PR พร้อมตรวจ ไม่ใช้คำว่าขึ้นเว็บแล้ว

งานค้าง/สิ่งที่ต้องให้ผู้รับช่วงตรวจต่อ:

- ระบุเฉพาะเรื่องที่ยังไม่ทำหรือมีข้อสงสัย พร้อมไฟล์/หลักฐานที่ใช้ต่อได้
