# ส่งต่องานใบเรียนรู้ประกอบไอดีคลังข้อสอบ

มาตรฐานงานของครูศตวรรษ บุตรคล้อ • 25 ตุลาคม 2026

งานนี้เพิ่มใบเรียนรู้ให้หัวข้อที่มีไอดีอยู่แล้วในคลังข้อสอบ Learning Hub ผลลัพธ์ต้องเป็นไฟล์เนื้อหาที่เชื่อมกับเมนูของไอดีจริง เปิดสอน เปิดเฉลย และพิมพ์ผ่าน Hub เดิมได้

## เริ่มใช้กับ AI อีกตัว

1. ส่งข้อความใน [STARTER-PROMPT-TH.txt](STARTER-PROMPT-TH.txt) ให้ AI
2. ส่ง [TASK-BRIEF-TEMPLATE.md](TASK-BRIEF-TEMPLATE.md) โดยกรอกหัวข้อ แหล่งต้นฉบับ และไอดีที่ทราบ ข้อมูลที่ยังไม่ทราบให้ AI ตรวจจากแหล่งจริง
3. ให้ AI อ่านคู่มือนี้ ตัวอย่างที่ยอมรับแล้ว และคู่มือสัญญาไฟล์ด้านล่าง
4. ใช้ [QA-CHECKLIST.md](QA-CHECKLIST.md) ตรวจและรับงาน

ถ้า AI อ่าน repo ไม่ได้ ให้แนบคู่มือนี้ พรอมป์ต์ คู่มือสัญญาไฟล์ HTML ตัวอย่างพร้อม assets เมนูเป้าหมาย และต้นฉบับของบทใหม่ อย่าให้เริ่มจากภาพหน้าจอเพียงอย่างเดียว และอย่าอ้างว่าอ่านเอกสารที่เข้าไม่ถึงแล้ว

หากครูสั่ง “วางแผนก่อน” ให้ส่งแผนเนื้อหาก่อนลงมือ หากครูสั่ง “ลุย” หรืออนุมัติการทำแล้ว ให้ดำเนินงานตามขอบเขตจนเสร็จ ไม่เพิ่มการขออนุมัติซ้ำทุกช่วง งานยาวแบ่งทำเป็นช่วงได้และต่อในไฟล์เดิมตามที่ตกลง

## ไกด์ประจำใบ

## วิธีคิดเนื้อหาให้เหมือนงานชุดนี้

- เป็นใบเรียนรู้สำหรับใช้สอนสดและให้นักเรียนเขียน ไม่อัดคำอธิบายจนกลายเป็นชีทอ่าน และไม่เปลี่ยนทั้งใบเป็นคำถามล้วน
- มีหัวข้อเนื้อหาจริง เช่น นิยาม เงื่อนไข สูตร ความสัมพันธ์ สรุปผลการทดลอง แล้วเว้นพื้นที่สำหรับสาระที่นักเรียนควรเขียน คำตอบครบอยู่ในช่องเฉลยของหัวข้อนั้น
- แทรกคำถามสั้นหลังประเด็นที่เพิ่งเรียน เพื่อให้แยกแยะและอธิบายได้ ก่อนเพิ่มคำถามที่เชื่อมหลายประเด็น
- ทุกข้อและทุกข้อย่อยต้องมีพื้นที่ตอบของตัวเองอยู่ใต้ข้อนั้น ไม่รวมหลายข้อไว้เหนือช่องว่างก้อนเดียว
- จัดขนาดพื้นที่ตามสิ่งที่จะเขียน: คำตอบสั้น เหตุผล สมการหลายขั้น หรือการคำนวณ ไม่สร้างบรรทัดเส้นประหรือบีบตัวอักษรเพื่อให้พอดีจำนวนหน้า
- ใช้หัวข้อเนื้อหา ตัวอย่าง และเลขคำถามธรรมดา ไม่ใช้ป้าย “จุดเช็ก”, “เช็กความเข้าใจ”, “จด”, “จำ”, “ฝึกเพิ่ม” หรือคำแปลเชิงกำกับเหล่านี้เป็นป้ายที่แต่งเพิ่ม ชื่อชุดคำถามทางการของต้นฉบับยังระบุเพื่อเทียบหนังสือได้
- เลขคำถามที่แต่งเพิ่มให้ต่อเนื่องกันทั้งไฟล์ ตัวอย่างนับแยกตามประเภท หากจัดคำถามจากหนังสือแทรกตามจุดเรียน ให้มีตารางติดตามว่าข้อเดิมไปอยู่ที่ใด
- เพิ่มคำถามเพื่อแก้ช่องว่างการเรียนรู้และฝึกทักษะซ้ำอย่างมีจุดประสงค์ เช่น เปลี่ยนตัวเลข เปลี่ยนสิ่งที่ถาม อ่านภาพกลับทาง หรืออธิบายเหตุผล ไม่เพิ่มจำนวนเพียงเพื่อให้ครบโควตา
- ใช้ภาพให้เด็กอ่านและอธิบาย ไม่บังคับวาดภาพอุปกรณ์ซ้ำเมื่อการวาดไม่ใช่จุดประสงค์ ถ้าสอนการเปรียบเทียบ ให้คงรูปร่าง มุมมอง สเกล และตัวแปรที่ควบคุมให้สัมพันธ์กัน
- ภาษาไทยและอังกฤษแยกเป็นสองชุดเต็ม ไม่สลับคละย่อหน้า ทั้งสองชุดมีหัวข้อ ข้อ/ข้อย่อย รูป ตัวเลข สูตร และคำตอบตรงกัน
- เฉลยต้องมีสาระครบ อธิบายเหตุผลและขั้นคำนวณเท่าที่จำเป็น ใช้สมการพร้อมหน่วย ตรวจเงื่อนไขและการประมาณ ไม่เขียนเพียงคำตอบสุดท้ายทุกข้อ

ไม่บังคับทุกบทให้เริ่มด้วยการทดลองหรือมีโครง 8 ช่วงเหมือน 10.2 เลือกลำดับตามเนื้อหาต้นฉบับและจุดประสงค์การเรียน

## ขั้นตอนทำงาน

### 1. รับงานและยืนยันหัวข้อ

- อ่าน `main` ล่าสุด, `AGENTS.md` ที่มีผลถ้ามี และไฟล์เดิมของหัวข้อก่อนแก้
- ยืนยัน subjectId, ชื่อหัวข้อ TH/EN, path ในคลัง, legacyId ถ้ามี และ bankKey จากหน้าหัวข้อ/catalog ที่ใช้งานจริง หรือเมนูเดิมที่ตรวจว่าตรงหัวข้อ ห้ามสร้าง hash จากชื่อหรือเอา ID ตัวอย่างมาแทน
- อ่าน [bank-id-authoring-guide.txt](../../public/content/templates/bank-id-authoring-guide.txt) สำหรับวิธีคัดลอก ID จากหัวข้อจริง ถ้าต้องอ่าน catalog ด้วยเครื่องมือ ให้ใช้ config ปัจจุบันใน [question-bank-config.js](../../public/shared/question-bank-config.js) และ client ปัจจุบัน ไม่ hardcode endpoint จากแชทเก่า
- ถ้าไม่มีเมนู ให้สร้างเมนูของ bankKey ที่ยืนยันแล้ว หัวข้อที่มีข้อสอบศูนย์ข้อก็มีสื่อประกอบได้ตามระบบเดิม
- ระบุไฟล์ที่รับผิดชอบและงานของผู้ช่วยอื่นก่อนเริ่ม ใช้ branch แยกหัวข้อ ไม่ reset หรือเขียนทับงานที่ไม่เกี่ยวข้อง

### 2. อ่านต้นฉบับและทำบัญชีเนื้อหา

อ่านช่วงหน้าที่ได้รับมอบหมายจริง แยกเลขหน้าหนังสือกับเลขหน้า PDF ตรวจครบทั้งข้อความ รูป คำบรรยาย ตาราง กิจกรรม ตัวอย่าง คำถามตรวจความเข้าใจ และแบบฝึกหัดที่เกี่ยวข้อง อ่านคู่มือครู/เฉลยที่ให้เพื่อยืนยันคำตอบ

ทำตารางสั้นในแผนงาน:

| ประเด็น/ข้อจากต้นฉบับ | หน้า/แหล่ง | ตำแหน่งในใบใหม่ | รูปที่ใช้ | สิ่งที่เพิ่ม/ยังไม่แน่ใจ |
| --- | --- | --- | --- | --- |
| ระบุตามงานจริง | แยก printed/PDF | ช่วง/หัวข้อ/เลขข้อ | ไฟล์หรือยังต้องเตรียม | ระบุให้ตรวจได้ |

อย่าแต่งว่าครบทั้งบทถ้ายังไม่ได้อ่านครบ อย่าข้ามข้อท้ายหน้าเพราะหัวข้อถัดไปเริ่มในหน้าเดียวกัน ใช้แหล่งหลักตรวจข้อเท็จจริงที่ไม่แน่ใจ และบันทึกการดัดแปลงให้ชัด

### 3. วางลำดับบทเรียน

ระบุแต่ละช่วงว่าจะมีหัวข้ออะไรให้นักเรียนเขียน ใช้ภาพใด ถามอะไรหลังจบประเด็น และเชื่อมไปสู่โจทย์อย่างไร คำถามจากหนังสือแทรกตามจุดเรียนได้ แต่ต้องตามกลับได้และครบตามขอบเขต แบบฝึกหัดท้ายหัวข้ออาจรวมไว้ท้ายใบเพื่อใช้ตรวจความเข้าใจภาพรวม

### 4. ทำไฟล์และภาพ

เริ่มจากโครงเนื้อหาของตัวอย่างหลัก ใช้ [learning-sheet-ai-prompt.txt](../../public/content/templates/learning-sheet-ai-prompt.txt) เป็นสัญญาไฟล์ รูปจาก PDF ของครูให้ตัดเองได้เมื่อมีเครื่องมือ เก็บภาพที่ต้องใช้และบันทึกแหล่งใน `assets/<หัวข้อ>/SOURCES.md` ถ้าหารูปจากอินเทอร์เน็ตต้องตรวจแหล่ง/สิทธิ์ใช้งานให้เหมาะสม

ภาพวิทยาศาสตร์ที่ต้องแม่นยำให้ใช้รูปต้นฉบับหรือ SVG/โค้ดที่ตรวจเรขาคณิตได้ ตรวจลูกศร มุม หน่วย กึ่งกลาง ระยะ สเกล และตัวแปรควบคุม รูปทุกไฟล์ต้องมีจริงและเปิดได้ กำหนด width/height ตามอัตราส่วนจริงเพื่อจองพื้นที่ก่อนภาพโหลด ป้ายในภาพใช้ EN ได้ โดยมี caption ของแต่ละภาษา

### 5. เชื่อมกับไอดีคลัง

ส่งมอบเป็นไฟล์ HTML ใบเรียนรู้, assets ที่ใช้จริง, เมนูของไอดีเป้าหมาย และบันทึกแหล่ง/QA ตามขอบเขต เมนูอยู่ที่:

`public/content/bank/<subjectId>/<real-bankKey>.html`

ภายใน `nav` ใช้ `data-menu-kind="tools"`, subjectId จริง, `data-chapter-id="bank"` และ `data-topic-id` ตรงกับ bankKey เพิ่ม anchor ของใบเรียนรู้ด้วย `data-tool-key="learning-sheet"`, `data-tool-kind="html"`, contentId คงที่ และ href ไปไฟล์จริง relative จากเมนู

contentId ใหม่ต้องไม่ซ้ำ ถ้าเป็นการแก้ใบเดิมให้รักษา contentId เดิม หากไอดีเดียวมีใบเรียนรู้หลายชิ้น ให้ใช้ tool-key/contentId แยกที่ไม่ชนรายการเดิมตามคู่มือ ไม่เขียนทับ anchor อื่น ปุ่ม Quiz/Notebook ของคลังระบบดูแลอยู่แล้ว หากเปลี่ยน route slug ที่เผยแพร่แล้ว ให้เก็บชื่อเดิมใน `data-route-aliases` ตามคู่มือ เพื่อให้ลิงก์เก่ายังเปิดได้

อย่าใช้ ID ของสลิตคู่หรือศูนย์กลางมวลกับบทใหม่ อย่าใช้เลขบทในหนังสือแทน bankKey อย่าแก้ generated route catalog, การตั้งค่า global, Apps Script หรือข้อมูลนักเรียนเพื่อเพิ่มใบเรียนรู้ธรรมดา

### 6. QA และเผยแพร่ตามสิทธิ์ของงาน

ใช้ [QA-CHECKLIST.md](QA-CHECKLIST.md) ตรวจเนื้อหาด้วยตนเอง คำนวณโจทย์ใหม่ ตรวจไฟล์และ build เปิด Hub จริง แล้วตรวจหน้าจอและฉบับพิมพ์ แยกสถานะให้ชัด: สร้างไฟล์ / ตรวจโครงสร้าง / ตรวจเนื้อหา / เปิด browser / central print preview / export PDF / native iPad / เผยแพร่

ใช้สิทธิ์ที่ครูให้ไว้ในแชทเพื่อดำเนินงานจนเสร็จ ถ้าให้เผยแพร่แล้วไม่ตั้งขั้นขออนุมัติใหม่เอง ถ้าไม่มีสิทธิ์เขียนหรือไม่มีเครื่องมือทดสอบ ให้ส่งไฟล์หรือ patch ที่วางได้จริงพร้อมสิ่งที่ต้องตรวจต่อ ห้ามสรุปว่า QA/เผยแพร่แล้วจากการอ่าน HTML อย่างเดียว

## สัญญาไฟล์ที่ต้องรักษา

- ราก HTML ใช้ `data-learning-html data-learning-sheet="1"` และ print metadata TH/EN ตามตัวอย่าง
- เฉลยอยู่ใน `data-sheet-answer` ที่เป็นลูกโดยตรงหนึ่งตัวของ `data-sheet-slot` เท่านั้น ภาษา TH/EN ใช้ semantic slot key คู่เดียวกัน ไม่รั่วคำตอบไปใน label/alt/attribute หรือข้อความซ้ำนอกช่อง
- ช่องเขียนเป็น block ใต้คำถามและกำหนดความสูงขั้นต่ำบนกระดาษด้วย `--sheet-print-height` หน่วย mm ไม่ซ้อนช่อง และไม่ใส่ช่องภายใน SVG
- relative link ไป `public/shared/learning-sheet.css` ต้องตรงกับระดับโฟลเดอร์จริง ระบบใช้ stylesheet นี้ติดตั้ง toolbar/ปุ่มจาก parent ตาม [HUB-DESIGN-SYSTEM.md](../../HUB-DESIGN-SYSTEM.md)
- สมการใช้ `\(...\)` หรือ `\[...\]` ภายใน text node เดียว ตรวจข้อจำกัดของ renderer จาก [html-math.js](../../js/html-math.js) โดยเฉพาะงานสูตรจำนวนมาก รวมสองภาษาแล้วต้องไม่เกินที่ระบบรองรับ
- ใช้ `data-print-keep` กับคำถาม+พื้นที่ตอบ รูป หรือกลุ่มเล็ก ห้ามครอบทั้ง section ยาวเกินหน้า ไม่กำหนด `@page` หรือทับ `.hub-print-*`
- ใช้ระบบภาษา เฉลย MathJax และพิมพ์เดิม ไม่เพิ่ม script, event handler, iframe, form, toolbar, CDN, ปุ่มพิมพ์ หรือ engine ใหม่ลงในไฟล์เนื้อหา
- งานนี้ใช้สัญญา `data-sheet-*` ของ Learning Sheet; สัญญา `data-review-*` ใน `docs/topic-review/` เป็นคนละเครื่องมือ อย่านำมาปะปนแม้ต่างมีคำถามและพื้นที่เขียน

## รูปแบบส่งงานกลับครู

แจ้งชื่อเรื่องกับไอดีคลัง, สิ่งที่สร้าง/แก้, ความครบของต้นฉบับและสิ่งที่เพิ่ม, ไฟล์/รูปที่ใช้จริง, จำนวนคำถาม/พื้นที่ตอบจากงานจริง, ผล QA พร้อมหลักฐานและข้อจำกัด และสถานะการเผยแพร่ ถ้าเผยแพร่แล้วให้ส่งลิงก์ตรงที่ตรวจว่าเปิดใบเรียนรู้ได้จริง ไม่ส่งเพียงลิงก์หน้าแรก

เมื่อมีหลายผู้ช่วย ให้แต่ละตัวระบุหัวข้อ/ไอดี/branch/ไฟล์ที่รับผิดชอบ และสรุปงานค้างให้ตัวรับช่วง ไม่จองหรือแก้ engine ส่วนกลางโดยปริยาย
