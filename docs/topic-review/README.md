## 1. ผลงานที่ต้องทำให้เหมือนกัน

นี่คือ **ใบเรียนรู้ทวนความจำแบบแบ่งเป็นช่วง** ไม่ใช่ข้อสอบ Mastery Quiz ใหม่ และไม่ใช่บทความสรุปยาวอย่างเดียว

แต่ละช่วงมี:

1. หัวข้อสั้น บอกสิ่งที่ต้องรู้/จำ
2. สรุปครบแกนสำคัญ นิยาม หลักการ สูตร เงื่อนไข หน่วย และข้อยกเว้นที่เกี่ยวข้อง
3. ภาพ/ตาราง/ตัวอย่าง เมื่อช่วยให้จำหรืออธิบายได้ง่ายขึ้น
4. คำถามเขียนตอบช่วยจำทันทีหลังเนื้อหาส่วนนั้น มีข้อย่อยได้
5. **พื้นที่เขียนแยกหลังแต่ละข้อย่อย** ไม่กองช่องว่างไว้ท้ายข้อใหญ่เพียงที่เดียว
6. เฉลยครบทุกข้อย่อย มีเหตุผลและวิธีทำเท่าที่จำเป็น โดยเริ่มซ่อน

ทำภาษาไทยและอังกฤษครบทั้งชุด ไม่สลับไทย–อังกฤษทีละย่อหน้าในหน้าที่เลือกภาษาเดียว ผู้เรียนเลือกด้วยปุ่ม TH/EN เดิม

ผู้ใช้ชอบให้เนื้อหาสั้น อ่านง่าย แต่ไม่ลดจำนวนประเด็นจนตกหล่น จำนวนข้อยืดหยุ่นตามหัวข้อ **ไม่จำเป็นต้องทำทุกเรื่องเป็น 12 ข้อหรือ 30 ข้อย่อย**

## 4. ไอดี 4 อย่างที่ต้องแยกให้ถูก

| ชื่อ | ตัวอย่าง / ความหมาย |
| --- | --- |
| `subjectId` | วิชาของคลัง เช่น `chemistry` หรือ `physics`; ปัจจุบันดูรายการที่รองรับใน `question-bank-model.js` |
| `legacyId` | ข้อความ ID เดิมเต็มจาก Sheet/Sitemap; อาจเป็นข้อความภาษาไทยยาว ๆ |
| `bankKey` | ID เผยแพร่รูป `b-` ตามด้วยเลขฐานสิบหก 24 ตัว; ใช้ชื่อไฟล์เมนูและเลือกบททวน |
| `contentId` | ID ของไฟล์ HTML ที่เราเขียน เช่น `chemistry-periodic-table-main-group-review`; ต้องไม่ชนกับไฟล์อื่น |

`topic slug` เช่น `periodic-table-main-group` เป็นชื่ออ่านง่ายสำหรับไฟล์/route metadata **ไม่ใช่ bankKey**

### วิธีหา bankKey หัวข้อใหม่

อ่าน `public/shared/question-bank-config.js` เพื่อใช้ endpoint ปัจจุบัน หรือใช้ bank client ของ repo แบบอ่านอย่างเดียว:

```bash
node --input-type=module - <<'JS'
import { bankClient } from './public/shared/question-bank-client.js';
const { sets } = await bankClient.catalog('chemistry');
console.log(JSON.stringify(sets, null, 2));
JS
```

เทียบ **วิชา + ชื่อเรื่อง + path ของบท + legacyId เต็ม** ก่อนเลือก `bankKey` คำชื่อซ้ำอาจอยู่คนละบทได้ อย่าเลือกผลลัพธ์แรกเพียงเพราะชื่อคล้ายกัน

- ห้ามสร้าง bankKey ด้วยการ hash ชื่อเรื่องเอง ห้ามใช้เลขแถว หรือเดาจากชื่อไฟล์
- หัวข้อที่ `questionCount: 0` ยังมีบททวนได้ หากเป็นหัวข้อที่เผยแพร่ใน catalog จริง
- หากไม่พบหรือระบุไม่ได้ชัด ให้ทำร่างเนื้อหาที่ไม่ขึ้นกับ ID ไปก่อนได้ แล้วขอ ID/หัวข้อให้ชัดก่อนลงทะเบียนจริง
- `route-catalog.v1.json` เกิดจาก build ไม่ใช่ไฟล์ทะเบียนที่ให้แก้ด้วยมือ

## 5. ทำไมกด Review จากข้อสอบรวมแล้วรู้ว่าจะเปิดเรื่องไหน

เส้นทางปัจจุบัน:

**Sheet คอลัมน์ B ของแถวโจทย์ → บริการ Apps Script จับกับ legacyId ที่เผยแพร่ → `reviewTopicKey` ของแถวนั้น → `topicIds` ของข้อใน Quiz → ปุ่ม Review → บททวนของ bankKey นั้น**

ข้อสอบหลายข้อที่อยู่ใน HTML แถวเดียวกันจะรับหัวข้อ B เดียวกัน ตัวอ่านใช้ ID ไม่เดาหัวข้อจากข้อความโจทย์

ฝั่งเนื้อหาบททวนใช้:

**เมนู `public/content/bank/<subjectId>/<bankKey>.html` → ลิงก์ `data-tool-key="review"` → ไฟล์สรุป → build route catalog → player เดิม**

งานสร้างสรุปหัวข้อใหม่ตามปกติจึงแก้เฉพาะ **ไฟล์เนื้อหา รูป และลิงก์เมนูของหัวข้อนั้น** ไม่ต้องแก้คอลัมน์ B หรือ Deploy Apps Script ทุกครั้ง

ระบบนี้ได้ Deploy บริการคอลัมน์ B รุ่น 5 แล้วเมื่อ 23 ต.ค. 2026 ในโปรเจกต์ **Learning Hub — บริการคลังข้อสอบ** ข้อมูลนี้ใช้วินิจฉัยระบบเท่านั้น ไม่ใช่คำสั่งให้แก้บริการในงานเขียนบททวนทั่วไป

งานที่เซฟไว้ยังคงโจทย์และ revision เดิมไว้; loader สามารถเติม metadata บททวนจากรุ่นปัจจุบันได้เฉพาะแถวที่เลขแถวและ HTML ตรงกัน ไม่เขียนทับคำตอบหรือย้าย revision เพื่อแก้ปุ่ม Review รายละเอียดอยู่ใน `services/question-bank/COLUMN-B-REVIEW.md`

## 7. สัญญา HTML ของบททวน

โครงหลักดูได้จาก template; marker เหล่านี้ต้องคงชื่อเดิม:

| Marker | ความหมาย |
| --- | --- |
| `<main data-topic-review-document>` | รากเนื้อหาที่ player นำไปแสดง |
| `data-content-lang="th"` / `"en"` | ภาษาไทยทั้งชุด / อังกฤษทั้งชุด |
| `<section data-review-question>` | คำถามใหญ่หนึ่งข้อ; ใช้ h3 เป็นหัวข้อคำถาม |
| `data-review-blank` | พื้นที่นักเรียนที่ต้องซ่อนเมื่อเปิดเฉลยข้อนั้น |
| `data-review-writing-space` | เปลี่ยนเป็นเส้นและช่องว่างตาม CSS กลาง |
| `<div data-review-answer hidden>` | เฉลยหนึ่งกล่องต่อคำถามใหญ่ เริ่มซ่อนเสมอ |

รูปแบบข้อย่อย:

```html
<section data-review-question>
  <h3>คำถาม 1 — ชื่อคำถาม</h3>
  <p><strong>ก.</strong> คำถามย่อยแรก</p>
  <div data-review-blank data-review-writing-space></div>
  <p><strong>ข.</strong> คำถามย่อยที่สอง</p>
  <div data-review-blank data-review-writing-space></div>
  <div data-review-answer hidden>
    <p><strong>ก.</strong> คำตอบและเหตุผลข้อแรก</p>
    <p><strong>ข.</strong> คำตอบและเหตุผลข้อที่สอง</p>
  </div>
</section>
```

คำถามต้องอยู่นอก `data-review-blank` เพื่อยังอ่านโจทย์ได้ตอนเปิดเฉลย หากใช้ตารางกรอกคำตอบ ให้ใส่ marker บนตารางหรือ wrapper เฉพาะตาราง แล้วใส่ตารางเฉลยครบใน answer

**ไม่ต้องเขียนปุ่มหรือ JavaScript เปิด–ปิดเอง** ระบบกลางสร้างปุ่มรายข้อใหญ่และเปิด–ปิดทั้งหมดให้ เมื่อเปิดเฉลย ช่องนักเรียนของข้อนั้นจะถูกซ่อน; สลับภาษา/เรื่องแล้วเฉลยเริ่มซ่อนใหม่

### ข้อจำกัดที่ทำให้หน้าตาใน source กับ player ต่างกันได้

ตัวอ่านคัดลอกเฉพาะแท็กที่รองรับ และไม่คัดลอก class/style/id ทั่วไป CSS ในหัวไฟล์ช่วยดู standalone แต่ไม่ควบคุมรูปลักษณ์ภายใน player

- ใช้ `p`, `strong`, `h2`, `h3`, `table`, `figure`, `figcaption`, `img`, รายการ และ marker เดิมเป็นหลัก
- อย่าพึ่ง `style=`, class ส่วนตัว, IDs หรือ event handlers เพื่อทำให้เนื้อหาจำเป็นปรากฏ
- ภายใน main ห้ามใส่ script, style, iframe, canvas, form, input, button, MathML หรือ media ที่ตัวอ่านจะทิ้ง
- `hidden` ทั่วไปจะทำให้เนื้อหาถูกทิ้ง; ใช้กับ answer ตามสัญญานี้เท่านั้น
- สูตรเป็น LaTeX text เช่น `\(E=hf\)`; display `\[...\]` เฉพาะสูตรหลักที่ต้องแยกบรรทัด หรือใช้ `sub` / `sup` กับสูตรเคมีสั้น ๆ
- SVG ภายนอกแบบคงที่ผ่าน `<img src="assets/name.svg" alt="...">` เหมาะกับแผนภาพแม่นยำ หลีกเลี่ยงภาพ AI สำหรับตัวเลข ตารางธาตุ ออร์บิทัล หรือข้อมูลที่ต้องเป๊ะ

## 8. มาตรฐานเนื้อหาและภาพ

- ทำรายการประเด็นก่อนเขียน: นิยาม → ความสัมพันธ์/หลักการ → ตัวอย่าง → ข้อยกเว้น → คำถามทวน
- เชื่อมเรื่องก่อนหน้าเท่าที่จำเป็น ไม่คัดทั้งบทเก่ามาใส่ซ้ำ
- ตรวจข้อมูลจากแหล่งหลัก เช่น สสวท./Project 14, งานต้นฉบับ, RSC, IUPAC หรือเอกสารหน่วยงานที่เกี่ยวข้อง ใส่ลิงก์แหล่งศึกษาต่อในบททวน
- เขียนสรุป คำถาม เฉลย และภาพขึ้นใหม่ ไม่คัดหนังสือทั้งหน้า/ข้อสอบทั้งชุด
- TH กับ EN ต้องเทียบกันได้: เลขข้อ ข้อย่อย ตัวเลข สูตร ตาราง หน่วย เงื่อนไข และคำตอบตรงกัน
- เน้นคำถามเขียนตอบ/เติมตาราง/วาด/อธิบาย ไม่เปลี่ยนเป็น MCQ โดยพลการ
- เฉลยต้องมีคำตอบทุกข้อย่อยและอธิบายจุดที่มักเข้าใจผิด ไม่ซ่อนเนื้อหาหลักทั้งหมดไว้ในเฉลย
- เว้นที่ตามงาน: ตอบสั้นใช้หนึ่งช่อง; อธิบาย/คำนวณ/วาดเพิ่มพื้นที่ตามความจำเป็น
- แผนภาพใช้ป้าย EN เพื่อใช้ร่วมกันทั้งสองภาษา; alt และ caption อยู่ในภาษาที่เลือก
- แผนภาพเชิงคุณภาพระบุว่าไม่ใช่มาตราส่วนจริง; ถ้าให้ค่าจำลองเพื่อฝึกอ่านข้อมูล ให้บอกชัด
- ลูกศรต้องชี้ถูก สัญลักษณ์ไอออน/สปิน/เลขยกกำลังไม่ตกหล่น อ่านได้บนจอเล็ก และพิมพ์ขาวดำแล้วยังแยกได้
- ตัวอย่างที่ผู้ใช้ชอบ: แผนผังลูกศรทแยงใช้เป็นภาพจำหลัก ลำดับยาวใช้ตรวจ และกฎ n+l เป็นส่วนเสริม

| เปิดบางข้อ | เฉลยเฉพาะข้อที่เปิด ช่องนักเรียนของข้ออื่นยังอยู่ |
| เปิดทั้งหมด | เฉลยครบ ไม่มีปุ่มควบคุมในกระดาษ |

ใช้เฉพาะภาษาที่เลือก พิมพ์ A4 ไม่มี UI ของ Quiz ติดไปด้วย และไม่กระทบคำตอบ/สมุด/คะแนนที่เซฟไว้ ตรวจสูตร ตาราง และรูปไม่ถูกตัด; หัวตาราง/สัญลักษณ์ต้องอ่านได้

## 10. ขั้นตอนทำงานหนึ่งหัวข้อให้เสร็จ

1. อ่านคำสั่งปัจจุบันของครูและไฟล์อ้างอิงที่เกี่ยวข้อง
2. เริ่ม branch แยกจาก main ล่าสุด ตรวจ git status และงานผู้อื่นก่อนแก้
3. ยืนยัน subjectId, legacyId, bankKey และบทจาก catalog จริง
4. ทำ content inventory และวางหัวข้อ/คำถาม แก้คำกำกวมด้วยหลักฐานหรือถามเฉพาะจุดที่จำเป็น ระหว่างรอให้ทำส่วนที่ไม่ขึ้นกับคำตอบต่อ
5. เขียน TH ทั้งชุดและ EN ทั้งชุด ใส่ช่องว่างทุกข้อย่อยและเฉลยครบ
6. สร้างรูปที่จำเป็น แล้วเพิ่ม review anchor ในเมนู bankKey เดิมหรือสร้างเมนูที่ยังไม่มี
7. ตรวจเนื้อหาด้วยตัวเองจากแหล่งหลัก ตรวจคำตอบ ตัวเลข หน่วย เงื่อนไข และข้อยกเว้น
8. รัน structural validation, unit tests และ production build
9. เปิด **ผ่าน player จริง** ตรวจ TH/EN รูป ปุ่มเฉลยรายข้อ/ทั้งหมด และหน้าจอเล็ก ตรวจ print states ตามความเปลี่ยนแปลงที่ทำ
10. ตรวจ diff ว่ามีเฉพาะไฟล์ของหัวข้อนี้ สร้าง PR อธิบายพฤติกรรมและผลตรวจให้ตรวจทานได้
11. Merge/เผยแพร่ตามขอบเขตที่ผู้ใช้อนุญาตในแชทนั้น หากขาดสิทธิ์ ให้ส่งไฟล์/patch ที่พร้อมวางแทน ไม่อ้างว่าเผยแพร่แล้ว
12. ตรวจ Actions สำเร็จ และตรวจ deployment.json/ไฟล์จริง/route บนเว็บ ก่อนแจ้งว่าเสร็จ
13. ส่งลิงก์ตรงบททวน ภาพยืนยันที่เหมาะสม และสรุปจำนวนคำถาม/ส่วนสำคัญสั้น ๆ

### คำสั่งตรวจมาตรฐาน

ใช้ Node ตาม `package.json` (ฐานนี้ Node >=24) และ pnpm ตาม `packageManager`; เริ่มจาก lockfile เดิม:

```bash
pnpm install --frozen-lockfile
node scripts/validate-topic-review.mjs public/content/reviews/chemistry/<topic-slug>.html
pnpm test:unit
pnpm build
git diff --check
```

ตรวจบททวนทั้งหมด:

```bash
node scripts/validate-topic-review.mjs --all
```

ร่างที่ยังไม่ลงทะเบียนเมนูตรวจเฉพาะเนื้อหาได้:

```bash
node scripts/validate-topic-review.mjs --content-only public/content/reviews/chemistry/<topic-slug>.html
```

`--content-only` ยังไม่ยืนยันว่า Review เปิดเข้าเรื่องได้ ต้องตรวจโหมดปกติและ route ก่อนส่งงาน ตัว validator ตรวจโครงสร้างและการผูกเมนู ไม่สามารถรับรองความถูกต้องทางวิชาการหรือความเหมาะสมของช่องว่างแทนครูได้

**ห้ามแก้ expected test count ให้ตรงเลขในเอกสารนี้** ใช้ชุดทดสอบจริงล่าสุด; ฐานส่งต่อผ่าน 330 unit tests ก่อนเพิ่มเครื่องมือส่งต่อนี้

### ลิงก์หัวข้อใน Learning Hub

```text
https://nixcentury.github.io/learning-hub/#<subjectId>/review/<bankKey>
```

ใช้ลิงก์นี้เมื่อต้องการหน้าต่างเครื่องมือและระบบแชร์/Back/Forward ของ Hub เดิม.
ปุ่มคลังเนื้อหาทบทวนบนหน้าคลังข้อสอบทั้งสองวิชาใช้หน้าต่างนี้แล้ว.
หัวข้อและไฟล์ยังอ้างจาก review anchor ในเมนู bankKey เดิม ไม่ต้องลงทะเบียนไฟล์ซ้ำ.

### ลิงก์ player เดิม (ยังรองรับ)

```text
https://nixcentury.github.io/learning-hub/pages/tools/topic-review-player.html?subject=<subjectId>&topic=<bankKey>&lang=th
```

ประกอบ URL จาก ID ที่ยืนยันแล้ว เปิดตรวจจริงก่อนส่งผู้ใช้ และตรวจการเลือก topic ว่าตรง ID มิใช่อ่านได้เพราะกดเลือกเรื่องอื่นด้วยมือ

สำหรับหัวข้อที่มีโจทย์ทดสอบในข้อสอบรวม ให้เปิดข้อที่มี B ตรงหัวข้อนี้แล้วกด Review อีกครั้ง; ถ้าหาโจทย์ทดสอบที่เหมาะสมไม่ได้ ให้แจ้งว่าตรวจ route/player แล้ว แต่ยังไม่ได้ทดสอบปุ่มจากข้อสอบรวม อย่าอ้างเกินสิ่งที่ลอง

### หลักฐานการเผยแพร่

- GitHub Actions build/deploy ต้องสำเร็จ
- `https://nixcentury.github.io/learning-hub/deployment.json` ต้องชี้ commit ที่มีงานของเรา (ถ้ามีคนอื่น merge ต่อ commit อาจใหม่กว่า ให้ตรวจ ancestry/ไฟล์ด้วย)
- ไฟล์เนื้อหาและรูปจริงต้องไม่ใช่รุ่นเก่า; เปรียบเทียบ bytes หรือส่วนที่เปลี่ยน
- `route-catalog.v1.json` ต้องมี route ที่ `subjectId`, `bankKey`, `toolKey: review`, `kind: content`, `status: ready` ตรงกัน และ content ชี้ source ที่ตั้งใจ
- หน้า player โหลดรูปครบ ภาษาและเฉลยถูก ไม่ขึ้น “กำลังเตรียม”

## 11. เมื่อมีหลายบัญชีทำพร้อมกัน

- แบ่งหัวข้อและ bankKey ให้ไม่ซ้ำกันก่อนเริ่ม; หนึ่ง branch ต่อหนึ่งงาน
- ชื่อไฟล์/asset ต้องสื่อหัวข้อ ไม่ใช้ `image1.svg` กลางร่วมกันจนทับงานอื่น
- ก่อน merge อ่าน main ล่าสุด ตรวจไฟล์ที่ชนและรักษาเครื่องมือที่อีกบัญชีเพิ่มไว้
- ไม่ force-push ทับ branch ผู้อื่น ไม่ reset/ลบไฟล์ที่ไม่ใช่งานตน
- อย่าเปิดแก้ Apps Script/Google Sheet เพื่อแก้ปัญหา content mapping โดยยังไม่ได้ตรวจเมนูและ route
- หากมีความขัดแย้งที่แก้ไม่ได้ ให้คง branch/patch ที่ตรวจแล้วไว้และระบุไฟล์ที่ต้องตัดสินใจอย่างชัดเจน

## 12. อาการที่เจอบ่อยและจุดตรวจ

| อาการ | ตรวจตามลำดับ |
| --- | --- |
| ยังขึ้นกำลังเตรียม | เมนู bankKey → review anchor → contentId/href → build catalog → commit/deploy จริง |
| Review ไปเรื่องอื่น | B ของแถว → legacyId ตรงวิชา/บทหรือไม่ → reviewTopicKey/topicIds → topic ที่ปุ่มเลือก |
| รูปไม่ขึ้น | path เทียบกับไฟล์เนื้อหา, ตัวพิมพ์ใหญ่–เล็ก, ไฟล์ถูก commit/deploy และ URL จริง |
| CSS source สวยแต่ใน player ไม่เป็นแบบนั้น | sanitizer ไม่คัดลอก class/style ทั่วไป; ใช้แท็กและ marker ที่รองรับ |
| ไม่มีปุ่มเฉลย | มี data-review-question และ answer หนึ่งกล่องอยู่ข้างในหรือไม่ |
| เปิดเฉลยแล้วยังมีช่องว่างกองอยู่ | marker data-review-blank ครอบพื้นที่นักเรียนครบหรือไม่ |
| คำถามหายตอนเปิดเฉลย | เอา prompt ออกจาก wrapper data-review-blank |
| เฉลยหลุดตอนพิมพ์ | ใช้ print button เดิม ตรวจ hidden/blank markers; อย่าเขียน print engine ใหม่ |
| งานเก่าบางข้อยังไม่รู้หัวข้อ | snapshot เดิมไม่มี metadata และแถว/HTML ไม่ตรงรุ่นปัจจุบัน; ห้ามเดาหรือ reset คำตอบเพื่อกลบปัญหา |

## 13. รูปแบบส่งงานกลับครู

บอกให้สั้นและตรวจสอบได้:

- หัวข้อที่ทำและจำนวนข้อใหญ่/ย่อย
- รายการประเด็นหลักที่ครูกำชับว่าครบแล้ว
- ลิงก์ตรงบททวนที่ตรวจแล้ว
- ผลตรวจจริงและข้อจำกัดที่ยังเหลือเฉพาะที่สำคัญ
- ภาพหน้าจอหลักฐานเมื่อมีการเปลี่ยนหน้าเว็บตามเครื่องมือที่ใช้

ไม่ต้องรายงานรายละเอียด Git/เครื่องมือทุกขั้น ไม่บอกว่า “เสร็จ” เพียงเพราะ commit สำเร็จ และไม่ขอให้ครู Deploy Apps Script ถ้าทำเพียงเพิ่มไฟล์บททวน
