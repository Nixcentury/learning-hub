# จัดการสมาชิกห้อง Hub ด้วยอีเมล

ฟีเจอร์นี้เป็นสมาชิกห้องใน Learning Hub ใช้ Firebase Realtime Database เดิม ไม่ใช้ Google Classroom API และไม่ต้องรอการอนุมัติแอปจากโรงเรียน

## ครูใช้ตรงไหน

เปิด Classroom → ห้องที่ตนเป็นเจ้าของ → **สมาชิกในห้อง**

- **เพิ่มนักเรียน**: กรอกอีเมลที่นักเรียนใช้ล็อกอิน Hub ด้วย Google ระบบเก็บเป็นรายการ **รอเข้า Hub** ได้แม้เด็กยังไม่เคยเข้าเว็บ เมื่อบัญชีที่ยืนยันอีเมลตรงกันเข้า Hub ระบบจะผูกสมาชิกโดยไม่ต้องกรอกรหัสห้อง ไม่ส่งอีเมลหรือแจ้งเตือนภายนอก
- **ยกเลิกรายการรอ**: ยกเลิกอีเมลที่ยังไม่เป็นสมาชิก
- **นำออก**: ต้องกดยืนยันอีกครั้ง ระบบลบเฉพาะสมาชิกและดัชนีห้อง พร้อมเก็บข้อมูลสมาชิกสำหรับคืนสิทธิ์ คะแนน คำตอบ งานที่ส่งและลิงก์เดิมไม่ถูกลบ นักเรียนบัญชีเดิมใช้รหัสหรือรายการอีเมลกลับเข้าห้องเองไม่ได้
- **คืนสมาชิก**: คืน UID ชื่อ วันที่เข้าและอีเมลเดิม ไม่สร้างบัญชีหรือประวัติคะแนนใหม่ การกรอกอีเมลของสมาชิกที่เคยนำออกก็คืนสมาชิกเดิมได้

อีเมลโรงเรียนสำหรับการส่งคะแนน Google Classroom อาจต่างจากอีเมล Hub ได้ ฟีเจอร์นี้ยังไม่จับคู่บัญชีสองระบบ ไม่เปลี่ยนการส่งออก CSV และไม่เปลี่ยนบัญชีที่เข้า Hub

## Rules ชุดเต็ม — ครูวางเอง

> รุ่นที่มีครูร่วมและโหมดฉุกเฉิน ให้ใช้ `firebase/classroom-assist.merged-draft.json` ตาม [คู่มือล่าสุด](../CLASSROOM-ASSIST-START-HERE.md) แทนชุด roster ด้านล่าง

ใช้ `firebase/classroom-roster.merged-draft.json` เป็น **Rules ชุดเต็ม** ที่ต่อจาก `classroom-links.merged-draft.json` และรวม Rules คะแนน คำตอบ งาน เงื่อนไขงาน ส่งซ้ำ และกล่องลิงก์เดิมแล้ว

1. สำรอง Rules ปัจจุบันก่อน ถ้ามีแก้ไขเองเพิ่มเติมนอกชุดกล่องลิงก์เดิม ให้เทียบ/รวมก่อนแทนที่
2. เปิด Firebase Console ของโปรเจกต์ Hub เดิม → Realtime Database → Rules
3. แทนข้อความทั้งชุดด้วยไฟล์เต็มนี้ แล้ว Publish ด้วยตนเอง ไม่วางเฉพาะส่วนสมาชิกทับ Rules ทั้งหมด
4. รีโหลด Hub ทั้งบัญชีครูและนักเรียน

ไม่มีการ deploy Rules จากโค้ดหรือ CI ก่อนวาง Rules ใหม่ การจัดการสมาชิกจะแสดงข้อผิดพลาดและปิดปุ่มไว้ การเข้าด้วยรหัสเดิมยังใช้ได้

สร้าง Rules เต็มใหม่ได้ด้วย:

```sh
node scripts/build-classroom-roster-rules.mjs
```

สคริปต์รับ baseline และ output เป็นอาร์กิวเมนต์ได้ และปฏิเสธ baseline ที่เปิด root หรือมีส่วนสมาชิกใหม่อยู่แล้ว ชุดทดสอบยืนยันว่า Rules นอกสมาชิก/ดัชนีห้องเทียบเท่าเดิม

## สิทธิ์และการโหลดข้อมูล

- ครูต้องได้รับอนุมัติและเป็นเจ้าของห้องนั้น จึงเพิ่มอีเมล ยกเลิกรายการรอ นำออกและคืนสมาชิกได้ ครูห้องอื่นและนักเรียนจัดการไม่ได้
- รายการอีเมลใช้ query ที่มี index ครูอ่านเฉพาะห้องที่เปิด นักเรียนอ่านได้เฉพาะ query อีเมลใน ID token ที่ยืนยันแล้ว ไม่มีรายชื่อผู้ใช้ทั้งระบบหรือการค้นอีเมลคนอื่น
- การเข้าห้องด้วยอีเมลตรวจ UID และอีเมลจาก Firebase Auth Rules ฝั่งเซิร์ฟเวอร์ การเปลี่ยนค่าในหน้าเว็บไม่ให้สิทธิ์เพิ่ม
- การเพิ่ม/นำออก/คืนสมาชิกยืนยันผลหลัง atomic write สำเร็จ การนำออกทำให้ห้องที่นักเรียนเปิดอยู่ถูกปิดเมื่อดัชนีสมาชิกอัปเดต ไม่ล้างคะแนนส่วนตัว
- Listener รายชื่อสมาชิก รายการรอและรายชื่อที่นำออกหยุดเมื่อปิดห้อง/ออกจาก Classroom/เปลี่ยนบัญชี ส่วน listener อีเมลของบัญชีตนเองทำงานระหว่างล็อกอินเพื่อรองรับการเข้าห้องอัตโนมัติ และหยุดเมื่อล็อกเอาต์/เปลี่ยนบัญชี

ใช้ Firebase แพ็กเกจเดิมได้ ไม่มี Cloud Functions ใช้โควต้า Realtime Database เดิมและไม่เพิ่มบริการเสียเงิน

## ตรวจสอบ

- Unit/UI: `pnpm test:unit`
- Firebase emulator: `pnpm test:classroom:roster` (ต้องมี database emulator JAR ตาม Classroom CI)
- Production Hub browser integration: `pnpm test:monitor:browser` ตรวจรายการรอ → บัญชีเข้า Hub ครั้งแรก → เข้าอัตโนมัติ → นำออกขณะเปิดห้อง → ปฏิเสธเข้าด้วยรหัส → คืนสมาชิก รวมหน้าจอมือถือและการแยกสิทธิ์นักเรียน

ชุด Rules ทดสอบการอ้างอีเมลคนอื่น อีเมลไม่ยืนยัน ข้ามบัญชี/ห้อง ครูถูกถอนสิทธิ์ partial write การปลอมข้อมูลสมาชิก/การลบตัวกันกลับเข้าห้อง และการรักษาคะแนน/งานเดิม
