# Learning Hub → Google Classroom ผ่านชีทใหม่

รุ่นนี้เป็นตัวกลางที่ครูสั่งเอง: ดาวน์โหลด CSV ของการบ้านจาก Hub → นำเข้าในชีทใหม่ → ตรวจรายชื่อ/คะแนน → กดส่งคะแนนฉบับร่างเข้า Google Classroom นักเรียนทำและแก้ข้อผิดใน Hub ตามเดิม ครูส่งออก CSV ใหม่เมื่อมีคำตอบรอบใหม่ ไม่มีการซิงก์เบื้องหลังในรุ่นนี้

ใช้ **ชีทใหม่และ Apps Script ใหม่** เท่านั้น ไม่ต้องเปลี่ยนโปรเจกต์ Cloud ของระบบเดิม ไม่แก้ชีทคะแนนเดิม และไม่ต้อง Deploy Web App

## ติดตั้งครั้งแรก — บัญชีครู

1. เปิดชีทใหม่ที่สร้างไว้ด้วยบัญชีครูโรงเรียนซึ่งเป็นครูใน Google Classroom ตั้งการแชร์เฉพาะครูผู้ดูแล เพราะชีทมีอีเมลและคะแนนนักเรียน
2. เลือก **Extensions → Apps Script** จะได้โปรเจกต์ใหม่ที่ผูกกับชีทนี้
3. แทนโค้ดตัวอย่างใน `Code.gs` ด้วยโค้ดทั้งหมดจาก [HubClassroomSheetBridge.gs](./HubClassroomSheetBridge.gs)
4. กด **+ → HTML** ตั้งชื่อ `ImportCsv` แล้ววางโค้ดจาก [ImportCsv.html](./ImportCsv.html) ชื่อต้องตรงกัน
5. ด้านซ้าย **Services → + → Google Classroom API → Add** ใช้ Version `v1` และ Identifier `Classroom`
6. แนะนำให้ไป **Project Settings → Show “appsscript.json” manifest file in editor** แล้วแทน manifest ของโปรเจกต์ใหม่นี้ด้วย [appsscript.json](./appsscript.json) ซึ่งกำหนดสิทธิ์เฉพาะชีทที่ผูกอยู่ รายชื่อห้องของครู และงาน/คะแนน Classroom ไม่มี Firebase secret
7. บันทึก กลับชีทแล้วรีเฟรช จะมีเมนู **Learning Hub** กด **1. เตรียมแท็บตัวกลาง** และอนุญาตด้วยบัญชีครู ตรวจบัญชีที่หน้าขอสิทธิ์ให้ถูกต้อง
8. กด **3. โหลดรายชื่อห้อง Google Classroom** ทดสอบว่าบัญชีครูเรียก API ได้จริง จะเห็นห้องที่เป็นครูและยัง ACTIVE ใน `HubCourses`

ถ้าใช้ Default Cloud project ที่ Apps Script สร้างให้อัตโนมัติ การเพิ่ม Advanced Service จะเปิด API ให้ในโปรเจกต์นั้น ไม่ต้องเปิด Cloud Console สำหรับขั้นตอนนี้ การอนุญาตจริงยังขึ้นกับนโยบายของโรงเรียน หากมีข้อความบล็อกโดยผู้ดูแล ให้หยุดที่หน้าดังกล่าวและส่งข้อความผิดพลาดให้ผู้ดูแลตรวจ ไม่ต้องเปลี่ยนโปรเจกต์เดิม

## ทดลองหนึ่งงานก่อน

1. ใน Learning Hub เข้าห้องในฐานะครูเจ้าของห้อง เปิดการบ้านที่เปิดรับการส่งงานแล้ว กด **ส่งออกไปชีท (.csv)** ในผลการส่งงาน
2. ในชีท เลือก **Learning Hub → 2. นำเข้า CSV จาก Hub** แล้วเลือกไฟล์ `hub-homework-….csv` โดยตรงผ่านกล่องนำเข้า ไม่ใช้ File → Import ของ Sheets
3. เปิด `HubUsers` เติม **ClassroomEmail คอลัมน์ C** ให้ตรงอีเมลโรงเรียนของนักเรียนแต่ละคน จับคู่ด้วย StudentUID/ชื่อจาก Hub ไม่ใช้เลขประจำตัวจากระบบเก่าแทน UID และห้ามให้อีเมลเดียวผูกกับสอง UID
4. คัดลอก CourseID ของห้องทดสอบจาก `HubCourses` ไปใส่ **คอลัมน์ L (CourseID)** ในแถวงานของ `HubAssignments` ตั้งคะแนนเต็มที่ **คอลัมน์ N (MaxPoints)** เป็นจำนวนเต็มมากกว่า 0 ค่าเริ่มต้น 100
5. คลิกหนึ่งเซลล์ในแถวงานนั้น แล้วเลือก **4. สร้าง/ตรวจงานของแถวที่เลือก** ตรวจห้อง ชื่องาน และคะแนนเต็มก่อนยืนยัน **งานใหม่จะประกาศให้ทั้งห้องเห็นทันที** พร้อมลิงก์ไปการบ้านเฉพาะห้องใน Hub จึงควรเริ่มกับห้องทดสอบ
6. สคริปต์บันทึก CourseWorkID และรหัสที่ผูกไว้ให้เอง ไม่ต้องกรอกหรือแก้รหัสเหล่านี้ กดซ้ำจะตรวจงานเดิมด้วยรหัสห้อง+การบ้าน ไม่ใช้ชื่อควิซจับคู่
7. เลือกแถวงานเดิมใน `HubAssignments` กด **5. ตรวจคะแนนก่อนส่ง** แล้วเปิด `HubReview` ตรวจ CourseName, CourseID, CourseWorkID, ชื่อ, อีเมล, Score, MaxPoints และ PreviousDraftGrade ให้ตรงกัน
8. กลับไปเลือกแถวเดิมใน `HubAssignments` แล้วกด **6. ส่งคะแนนฉบับร่างที่ตรวจแล้ว** ภายใน 10 นาที รายการ READY จะเขียน `draftGrade` สูงสุดครั้งละ 25 คน สคริปต์ตรวจข้อมูลซ้ำก่อนส่ง หากข้อมูลเปลี่ยนต้องกดเมนู 5 ใหม่
9. ดู `HubSyncLog` และเปิดงานใน Google Classroom ตรวจคะแนนจริง ครูเป็นผู้คืนงาน/ประกาศคะแนนให้นักเรียนตามปกติ การส่งคะแนนของสคริปต์ไม่ได้ส่งงานแทนนักเรียน
10. ถ้ามี NEXT_BATCH ให้ทำเมนู 5–6 ซ้ำ งานที่ส่งสำเร็จแล้วจะเป็น ALREADY_SENT ถ้านักเรียนแก้ข้อผิดและส่งใหม่ ให้ส่งออก CSV ใหม่จาก Hub แล้วทำเมนู 2 และ 5–6 อีกครั้ง ใช้คะแนนรวมรอบล่าสุด แม้จะต่ำกว่ารอบก่อน

## สถานะที่พบบ่อย

| Status ใน HubReview | ความหมาย/การจัดการ |
| --- | --- |
| READY | ตรวจพบงานของนักเรียน พร้อมส่งฉบับร่างเมื่อครูกดยืนยัน |
| ALREADY_SENT | รอบคำตอบนี้ส่งสำเร็จไปยังงานและอีเมลนี้แล้ว ไม่เขียนซ้ำ หากครูแก้คะแนนใน Google เอง สคริปต์จะรักษาคะแนนนั้นจนมีรอบส่งใหม่ |
| NOT_SUBMITTED | ยังไม่ส่งจาก Hub เว้นคะแนนไว้ ไม่ส่ง 0 |
| GRADING_ERROR | ตรวจคำตอบจาก Hub ไม่ได้ ข้ามรายการนี้และตรวจข้อมูลต้นทาง |
| NOT_IN_EXPORT | ไม่อยู่ในรายชื่อของ CSV ล่าสุด ข้ามรายการนี้ |
| MISSING_EMAIL / INVALID_EMAIL | เติมหรือแก้อีเมลใน HubUsers แล้วตรวจใหม่ |
| DUPLICATE_EMAIL / DUPLICATE_GOOGLE_USER | พบการจับคู่คนซ้ำ ต้องแก้ก่อนส่ง |
| NO_SUBMISSION | Google ยังไม่มีรายการของนักเรียนสำหรับงานนี้ ตรวจว่าคนนี้อยู่ในห้องและได้รับงานแล้ว |
| AMBIGUOUS_SUBMISSION | พบรายการมากกว่าหนึ่ง ไม่ส่งอัตโนมัติ |
| API_ERROR | อ่านรายละเอียดข้อผิดพลาด ตรวจบัญชี สิทธิ์ และบริการ Classroom ก่อนลองใหม่ |
| NEXT_BATCH | เกิน 25 รายการที่ตรวจผ่าน API ในรอบนี้ ส่งชุดแรกและแก้ข้อผิดพลาดก่อน แล้วตรวจใหม่ |

## พฤติกรรมและขอบเขต

- ต้องใช้ Apps Script **โปรเจกต์เดิมชุดนี้** ต่อไปสำหรับงานที่มันสร้าง การคัดลอกชีท/สร้างสคริปต์ใหม่ไม่ได้ทำให้โปรเจกต์ใหม่แก้คะแนนงานเก่าได้ อย่าเปลี่ยน Cloud project ของสคริปต์นี้หลังเริ่มใช้
- รุ่นนี้สร้างงาน Google ใหม่ผ่านสคริปต์ และตรวจ `associatedWithDeveloper` ก่อนส่งคะแนน ไม่รองรับการใส่รหัสงานที่สร้างด้วยมือหรือด้วยสคริปต์เก่า
- การเปลี่ยนคำชี้แจง/ปิดงานใน Hub ไม่เปลี่ยน Google Classroom อัตโนมัติ และการคืนงานใน Google ไม่ปิดการแก้ข้อผิดใน Hub ครูจัดการทั้งสองแห่งได้ตามต้องการ
- CSV มีคะแนนรวมที่คำนวณใหม่จากคำตอบและชุดคำถามที่ตรึงไว้ของการบ้าน ฝั่งครูสามารถตรวจไฟล์และแก้ชีทได้ จึงเหมาะกับตัวกลางที่ครูตรวจเอง ไม่ใช่หลักฐานคะแนนที่ยืนยันจากเซิร์ฟเวอร์สำหรับการซิงก์อัตโนมัติ
- คะแนน Google คำนวณจาก `Score / MaxScore × คะแนนเต็ม Google ปัจจุบัน` ปัดสองตำแหน่ง ไม่ใช้ Percent ที่ปัดไว้คำนวณซ้ำ งาน Google ที่ไม่กำหนดคะแนนเต็ม/คะแนนเต็ม 0 จะถูกปฏิเสธ
- ไฟล์มีข้อมูลการบ้านหนึ่งแถวเสมอ สร้างงานได้แม้ยังไม่มีนักเรียนส่ง ส่วนคะแนนว่าง/ข้อผิดพลาดไม่กลายเป็น 0 คะแนน
- นำเข้าไฟล์ซ้ำไม่เพิ่มรายการซ้ำ ไฟล์ส่งออกเก่าถูกข้าม รอบส่งย้อนหลังหรือรอบเดิมที่คะแนนขัดแย้งจะถูกปฏิเสธ จับเวลานำเข้าด้วย ExportedAt ใน CSV ซึ่งมาจากนาฬิกาเครื่องครู
- ต้องนำเข้า CSV ใหม่เมื่อต้องการคะแนนล่าสุด ถ้ามีการส่งใหม่หลังดาวน์โหลดไฟล์ สคริปต์ไม่สามารถรู้ได้จนกว่าจะนำเข้าไฟล์ใหม่
- ถ้าการส่งหยุดกลางทาง ให้ตรวจใหม่และลองส่งอีกครั้ง รายการที่บันทึก SENT แล้วจะถูกข้าม หาก Google รับคะแนนแต่การตอบกลับ/บันทึก log หาย อาจส่งฉบับร่างค่าเดิมซ้ำได้ การ retry ไม่ประกาศคะแนนหรือส่งงานแทนนักเรียน
- ระหว่างสคริปต์ทำงานให้รอจนจบก่อนแก้แท็บข้อมูล อย่าสลับ/ลบหัวคอลัมน์ ใส่สูตร หรือแก้คะแนน/รหัสที่สคริปต์ดูแล ช่องที่ครูควรแก้คือ ClassroomEmail, CourseID ก่อนผูกงาน และ MaxPoints ก่อนสร้างงาน
- ไม่มีการแก้ Firebase Rules ในฟีเจอร์นี้ เด็กใช้ Hub เหมือนเดิม อีเมลที่ล็อกอิน Hub อาจต่างจากอีเมลโรงเรียนได้ในรุ่นนี้ เพราะครูจับคู่ UID → อีเมล Classroom ไว้อย่างชัดเจน

## การทดสอบ

`pnpm test:assignments` ทดสอบ CSV จริงร่วมกับ Apps Script V8 ผ่านบริการจำลอง ครอบคลุมนำเข้าซ้ำ/เก่า รอบส่ง อีเมล รหัสงาน กรณี acknowledgement หาย ตรวจรายการ และ draftGrade ส่วน `pnpm test:monitor:browser` ตรวจปุ่มครู/ไฟล์ดาวน์โหลดจริงกับ production build และ Firebase emulator

ยังต้องให้ครูทดสอบสิทธิ์ Google โรงเรียนและการเขียนคะแนนจริงตามขั้นตอนข้างต้น การผ่านบริการจำลองไม่ได้ยืนยันว่าบัญชีโรงเรียนอนุญาต
